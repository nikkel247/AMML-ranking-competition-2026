# AMML Ranking Competition 2026

Ранжирование русскоязычных фрагментов (Википедия): для каждого запроса нужно упорядочить кандидатов так,
чтобы релевантные оказались выше. Метрика — NDCG@10, релевантность бинарная.

Всё решение находится в одном ноутбуке: лексическая модель на CatBoost + несколько нейросетевых
кросс-энкодеров + стекинг, смешанный с калиброванным базовым ансамблем.

## Как запустить

1. Положить `train.csv`, `test.csv`, `sample_submission.csv` в папку `data/` или рядом с ноутбуком
   (либо указать папку в переменной `AMML_DATA_DIR`).
2. Открыть `solution.ipynb` и выполнить все ячейки сверху вниз.

Итог — файл `submission.csv` (колонки `id,prediction`) в `AMML_OUTPUT_DIR`
(по умолчанию `/kaggle/working`, если такая папка есть, иначе текущая).

### Что нужно знать про запуск

* **Интернет** нужен при первом запуске: веса моделей скачиваются с Hugging Face.
* **GPU необязателен.** Если он есть, первая ячейка записывает `gpu_scores.py` и считает zero-shot скоры
  энкодеров в `amml_pre/`. Без GPU эта ветка пропускается, и скоры считаются на CPU (ONNX / PyTorch) —
  это самая долгая часть, но результаты кешируются порциями и после обрыва расчёт продолжается с места остановки.


## Путь решения

### 1. Данные и ключевые наблюдения

Строка — пара «запрос, фрагмент» с полями `query`, `title`, `text`, идентификаторами
`query_id / document_id / article_id` и мета-информацией (`ingest_source`, `passage_index`,
`article_passage_count`, `article_char_count`). Данные «грязные»: HTML-теги и сущности, ударения и невидимые
символы, заглушки вместо заглавий («—», «не указано», `nan`), хвосты «— Википедия», числовые поля с пробелами,
запятыми и отрицательными значениями.

Что определило дизайн:

* **Запросы в test не пересекаются с train**, статьи почти не пересекаются. Обычная кросс-валидация по запросам
  завышает качество: одна и та же статья или документ попадает и в fit, и в val.
* Поэтому валидация везде **по «темам»**: запросы объединяются в группу, если делят документ или редкую статью
  (≤ 2 запросов); группы — компоненты связности графа (`topic_groups`, `strict_split`).
* Для ранжирования важен порядок внутри запроса, поэтому скоры переводятся в z-оценки внутри запроса
  (`within_query`).

### 2. Предобработка

`clean`: `html.unescape`, NFKC/NFC, удаление диакритики и zero-width символов, вырезание тегов и сносок `[12]`,
схлопывание пробелов, отбрасывание «пустых» значений. Заглавия очищаются от «— Википедия», пропущенные
восстанавливаются по другим фрагментам той же статьи (`clean_titles`). Для нейросетей фрагмент подаётся как
`«заглавие. текст»`.

### 3. Лексическая модель (CatBoost)

Базовый слой — сотни признаков на пару (`rank_features`), модель — `CatBoostClassifier` (700 итераций, depth 6):

* **Леммы и словоформы** (`pymorphy3`, `ё→е`, стоп-слова вопросов): покрытие, IDF-взвешенное покрытие,
  BM25-подобный скор, позиция первого вхождения, доля в первых 30 словах, частота, n-граммы (2–3), «окно»
  максимального покрытия и его плотность — по тексту и по заглавию.
* **Символьный TF-IDF** (`char_wb`, 3–5-граммы, до 170 тыс. признаков): косинусы запрос–текст, запрос–заглавие,
  заглавие–текст, запрос–начало текста.
* **Сущности**: слова с заглавной буквы в запросе против текста и заглавия; нечёткое совпадение заглавия
  (`rapidfuzz`); совпадение годов.
* **Тип вопроса**: regex-шаблоны ответа (даты, размеры, «родился», «умер», «основан», «население», «где
  находится», «перевод») и соответствующие маркеры в запросе.
* **Лучшее предложение**: максимальный IDF-скор предложения и его позиция.
* **Структура и технические признаки**: длина, число скобок/запятых/цифр, индекс фрагмента в статье,
  относительная длина, форматы и пропуски числовых полей, артефакты разметки (ударения, nbsp, переносы, HTML).
* **Контекст запроса и статьи**: размеры групп, число запросов на статью/документ и для ключевых признаков —
  ранг в запросе, отставание от лучшего, среднее/максимум по статье.

### 4. Нейросетевые кросс-энкодеры

| Имя | Модель | Роль |
|---|---|---|
| `jina` | `jinaai/jina-reranker-v2-base-multilingual` | основной сильный скор |
| `mini` | `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1` | лёгкий вспомогательный |
| `dity` | `DiTy/cross-encoder-russian-msmarco` | русскоязычный, доп. сигнал |
| `modern` | `ARGA100/ru-reranker-modernbert-small` | доп. сигнал |
| `bge` / `ft_bge` | `BAAI/bge-reranker-v2-m3` (zero-shot / дообученный) | GPU-режим |

Скоры берутся в порядке приоритета: (1) готовые `amml_pre/scores_<имя>.npz`; (2) ONNX на CPU
(`onnxruntime`, квантизованные `jina` и `mini`, ревизии HF зафиксированы); (3) PyTorch на CPU с int8-квантизацией —
для энкодеров без ONNX (`dity`, `modern`). Кеш привязан к хэшу данных и параметров.

`gpu_scores.py` (встроен в ноутбук) умеет:

* `zeroshot` — fp16/bf16-инференс по train и test;
* `finetune` — дообучение кросс-энкодера с **listwise-лоссом (ListNet)** по запросам: 5 фолдов GroupKFold по
  темам, 2 эпохи, `lr=1e-5`, чекпоинты по фолдам. На выходе — OOF-скоры для train и усреднённые по фолдам для
  test, так что стекер получает честные скоры дообученной модели без утечки.

### 5. Базовый ансамбль с калибровкой

* Классический ансамбль: `0.85·z(jina) + 0.07·z(mini) + 0.08·z(lexical)`.
* **Калибровка jina** (`fit_jina_calibration`): к z-скору добавляется линейная поправка по 8 признакам
  (`text_acute`, `q_a_count`, `char_qt`, `plem_weighted`, `entity_t`, `p_chars`, `rel_index`, `d_q_count`).
  Коэффициенты подбираются **попарной логистической функцией потерь** (релевантный против нерелевантного внутри
  запроса) с L2 и ограничением |коэффициента| ≤ 0.25, чтобы поправка лишь корректировала нейросеть.
* Итог базы: `0.5·blend + 0.5·calibrated_jina`.

### 6. Стекинг

CatBoost обучается поверх скоров энкодеров. Признаки:

* для каждого энкодера (`listwise`): сырой скор, z-оценка, ранг, отрыв от лидера, максимум и разброс по запросу,
  softmax-вероятность, число «сильных» кандидатов, максимум/среднее/ранг/число по статье;
* **PRF-сходство** (pseudo-relevance feedback): насколько фрагмент похож (символьный TF-IDF) на те фрагменты
  запроса, которые нейросети считают релевантными — взвешенно, по топ-3 и максимум; отдельно для сводного скора
  и для jina;
* честный **out-of-fold лексический скор** (`lexical_oof`), чтобы стекер не видел «подсмотренных» ответов;
* избранные лексические и структурные признаки.

Модели стекера: `CatBoostRanker` (YetiRank, ранняя остановка по `NDCG:top=10` на отложенных темах, до 1500
итераций) и `CatBoostClassifier` (500 итераций), по 3 сида. Обучение на 2 400 запросах train порциями по 400
с кешем нейро-скоров — так расчёт укладывается в CPU-время.

### 7. Итоговая смесь

`prediction = w · z(стекер) + (1 − w) · z(калиброванная база)`, где стекер — смесь ранкера и классификатора.
Оба веса выбираются по сетке на OOF-предсказаниях 5-фолдовой валидации по темам.
Выбрано: классификатор внутри стекера — 1.0, стекер в итоговой смеси — 0.5.

## Результаты (OOF NDCG@10, 5 фолдов по темам, 2 400 запросов)

| Модель | NDCG@10 |
|---|---|
| энкодер `dity` (zero-shot, PyTorch int8 на CPU) | 0.8031 |
| энкодер `mini` | 0.8477 |
| энкодер `jina` | 0.9530 |
| исходный ансамбль (jina + mini + lexical, калибровка) | 0.9555 |
| CatBoostRanker (стекер) | 0.9542 |
| CatBoostClassifier (стекер) | 0.9578 |
| **0.5 · стекер(классификатор) + 0.5 · исходный ансамбль** | **0.9582** |

Наблюдения:

* `jina` — единственный энкодер, близкий к потолку сам по себе; остальные дают дополнительные сигналы.
* В стекере классификатор оказался лучше ранкера, поэтому сетка выбрала ему полный вес.
* Смесь стекера и базы стабильнее по фолдам, чем каждая часть отдельно (например, фолд 0: ранкер 0.9595 /
  классификатор 0.9656 / база 0.9612; фолд 2: 0.9431 / 0.9498 / 0.9463).
* Валидация по темам даёт цифры ниже наивной валидации по запросам, зато ближе к тому, что будет на test.

## Ограничения и заметки

* В зафиксированном прогоне энкодер `modern` не загрузился (на Hugging Face не нашёлся `config.json`) и был
  автоматически пропущен — итоговый ансамбль работал на `jina + mini + dity`.
* В этом прогоне `jina` и `mini` брались из готовых `amml_pre/scores_*.npz`, а `dity` считался на CPU через
  PyTorch с int8-квантизацией; на GPU без квантизации его вклад может быть выше.
